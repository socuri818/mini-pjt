### RAGAS 측정 (round1 이후)

방법: `evaluation/ragas_eval.py`가 실행 중인 서버의 `/query` 응답을 모아 RAGAS 4개 지표를 계산한다.
- 대상: 정답 참고문(`evaluation/ragas_references.csv`)이 있는 7개 문항(#1, #2, #3, #4, #5, #9, #10). 검색 근거가 없는 #6~#8, #11, #12는 제외했다.
- `contexts`에는 검색한 문서 조각과 **도구 결과**(훈련표·페이스·기록)를 함께 넣었다. 답변의 수치는 문서가 아니라 도구에서 나오기 때문이다. 시스템이 덧붙인 출처·더미 안내 줄은 평가용 답변에서 뺐다.
- 평가 LLM은 에이전트와 같은 Claude Sonnet 4.5이고 임베딩은 Titan v2다. 정답 참고문은 수집 문서와 도구 규칙에서 작성했으며 사람 검토가 필요하다.

| 측정 | 상태 | context_recall | context_precision | faithfulness | answer_relevancy |
|---|---|---|---|---|---|
| ragas1 | contexts에 도구 결과 포함 직후 (모델: global 프로필) | 0.798 | 0.545 | 0.816 | 0.345 |
| ragas2 | 검색어 규칙(질문 문장 그대로, 내용별 검색) 추가 | 0.733 | 0.464 | 0.797 | 0.462 |
| ragas3 | ragas2와 같은 조건 재측정 | 0.733 | 0.465 | 0.802 | 0.416 |
| ragas4 | 훈련표 요청에 증가율 문서 검색 고정 + 검색 결과 누적 버그 수정 (모델: us 프로필) | 0.833 | 0.620 | 0.786 | 0.434 |
| **ragas5** | 테이퍼 문서(04)에 표 내용을 글로 풀어 쓴 문장 추가 후 | **0.964** | **0.632** | **0.784** | **0.421** |

읽는 법
- **context_recall은 0.798 → 0.964로 개선**됐다. 원인은 검색이었다. 모델이 만드는 검색어가 매번 달라져 #3은 롱런 목적 문서(10번)를, #4는 테이퍼 표 조각을 놓치곤 했다. 검색어 규칙, 검색 결과 누적(여러 번 검색하면 마지막 결과가 앞 결과를 덮어쓰던 버그 수정), 표를 글로 풀어 쓴 문장이 함께 효과를 냈다.
- **faithfulness는 0.78~0.82에서 움직이며 기준 0.8을 확정적으로 넘지 못했다.** ragas1~3은 0.80 안팎, ragas4·5는 0.78이다. 낮은 문항은 #4(0.58)와 #5(0.64)로, 답변이 문서에 없는 해석("거리를 절반 정도로")이나 추가 설명을 덧붙인 경우다. 샘플이 7개이고 같은 측정을 반복해도 ±0.02 안팎이 흔들려, 이 값만으로 기준 충족 여부를 단정할 수 없다.
- **answer_relevancy는 0.35~0.46으로 낮다.** 긴 한국어 답변(표·주의사항 포함)에 낮게 나오는 경향이 있고, 답변이 "문서에 없다"고 하면 0이 된다(#3의 이전 측정). 이 값만으로 답변 품질을 판단하기는 어렵다.
- **context_precision은 0.46~0.63이다.** 도구 결과는 정답에 직접 쓰이지만 검색 조각 중 일부는 질문과 관련이 적다. 검색에 관련도 기준이 없어 질문과 무관한 조각이 3개까지 채워지는 한계가 있다.
- ragas1~3은 `global.anthropic…` 프로필, ragas4·5는 같은 모델의 `us.anthropic…` 프로필이다. Bedrock 일일 토큰 한도 때문에 바꿨다.
- 이 측정은 7개 문항 1회씩이고, 케이스 CSV는 수정하지 않았다. 원자료는 `evaluation/results/ragas*.md|json`이다.
- **이 측정과 재채점 뒤에 바뀐 것(재측정 전)**: 수집 문서를 10건에서 16건으로 늘렸고(대회 중 탄수화물·젤·수분·전해질 6건), 프롬프트에 영양·수분 질문을 범위로 명시했으며, 검색을 동시에 여러 번 호출할 때 Chroma 클라이언트 충돌로 검색이 실패하던 버그를 고쳤다(클라이언트를 한 번만 만들고 검색을 직렬화). 문서가 늘어 기존 질문의 검색 결과가 바뀔 수 있어, #3·#4 등 핵심 질문의 검색 상위 3개가 그대로임은 확인했지만 RAGAS와 재채점은 Bedrock 일일 한도 때문에 다시 돌리지 못했다.

## 5. 다음 개선 (round2 대상)

1. **faithfulness 0.8 확보**: #4·#5처럼 답변이 문서에 없는 해석을 덧붙이는 경우를 줄이는 방법 (프롬프트, 규칙 2 필터 확대)
2. **context_precision**: 검색에 관련도 기준(임계값)을 두어 질문과 무관한 조각이 contexts에 들어오지 않게 하기
3. **#9, #10**: 훈련표 요청에서 동의를 구하거나 도구를 건너뛰는 경우 줄이기

5. 문서에 근거가 없는 일반론(예: "대회 전날 완전 휴식")이 답변에 섞이는 문제 — 규칙 2 필터가 수치만 보는 한계

## 6. 재현 방법

```
python -m src.retriever --rebuild        # 문서 인덱스 생성 (최초 1회)
python evaluation/run_eval.py --judge --repeat 3 \
  --runner with_records=R001 --runner no_records=R099 \
  --server-cmd "python -m uvicorn src.api_server:app --port 8000" --out evaluation/results/round1
```

RAGAS 측정은 서버를 띄운 상태에서 다음처럼 실행한다. (`pip install -r requirements.txt` 필요, 평가 정답은 `evaluation/ragas_references.csv`)

```
python evaluation/ragas_eval.py --base-url http://127.0.0.1:8000 --out evaluation/results/ragas1
```

원자료(`evaluation/results/*.md|json`)는 로컬 산출물이며 `.gitignore` 대상이다.
